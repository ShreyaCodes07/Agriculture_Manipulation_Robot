About the Project

Project abstract, engineering objectives, problem formulation, and comparative analysis.

Abstract

Agricultural automation plays a vital role in addressing farm labor shortages and improving harvesting efficiency. This project presents a simulation-first autonomous mobile manipulator robot designed for field navigation, fruit detection, obstacle avoidance, and fruit harvesting. The system integrates Python OpenCV computer vision, a 2D kinematic field simulator, and a FastAPI-based monitoring dashboard.

Problem Statement

Traditional harvesting methods require intensive human labor, are time-consuming, and expose workers to grueling field conditions. Conventional static automation lacks mobilty across uneven plant rows. There is a need for an affordable, intelligent mobile robotic platform that can detect ripe fruits in real-time, avoid obstacles dynamically, and execute targeted pick-and-place operations.

Target Applications

  • Selective greenhouse fruit picking (tomatoes, apples, citrus).
  • Automated row navigation and field mapping.
  • Real-time crop health & soil moisture monitoring.

System Limitations

  • 2D simulation does not account for complex 3D terrain slopes.
  • HSV vision sensitive to extreme outdoor lighting shifts.
  • Payload limited by SG90/MG90S servo torque capacity.

Power Safety & Isolation Notes

Crucial Safety Rule: Never power the L298N motor driver or servos directly from the Arduino 5V pin. DC motors and servos induce inductive voltage spikes that can crash or burn the microcontroller. Use a dedicated 12V battery line for motor power and step-down LM2596 buck converter for servos, sharing a common ground (GND) wire.

Documentation & Viva Voce Preparation

Project report summary, presentation slide structure, and 25+ viva voce examination questions with answers.

Search Viva Voce Question Bank

Q1: What is the main objective of this Agriculture Manipulation Robot project? ▼
The primary objective is to design and develop a simulation-first autonomous mobile robot equipped with a 4-DOF manipulator arm and computer vision to navigate plant rows, detect ripe fruits, avoid obstacles, pick target crops, and deposit them into an onboard basket while monitoring soil health.
Q2: Why use HSV color space instead of RGB for fruit detection in OpenCV? ▼
RGB combines color brightness and chromaticity across all three channels, making it highly sensitive to outdoor sunlight changes and shadows. HSV (Hue, Saturation, Value) separates pure color information (Hue) from lighting intensity (Value), enabling robust color segmentation under varying illumination.
Q3: How does the L298N motor driver control the chassis motors? ▼
The L298N is a dual H-bridge motor driver. It uses digital input pins (IN1-IN4) to switch current direction through the motor coils (controlling forward/reverse rotation) and PWM pins (ENA, ENB) to adjust voltage duty cycles for speed control.
Q4: What is inverse kinematics in the context of the 4-DOF robotic arm? ▼
Inverse Kinematics (IK) is the mathematical calculation used to determine the required joint angles (θ1, θ2, θ3) needed to position the end-effector gripper at a specific 3D target coordinate (X, Y, Z) near the identified fruit.
Q5: How does the HC-SR04 ultrasonic sensor measure obstacle distance? ▼
The HC-SR04 emits a high-frequency ultrasonic sonic pulse (40 kHz) from its transmitter. It measures the time elapsed (\(t\)) until the echo returns to the receiver. Distance is calculated using the formula: \(\text{Distance} = \frac{\text{Speed of Sound } (343 \text{ m/s}) \times t}{2}\).
Q6: Why is FastAPI preferred over Flask or Django for this backend application? ▼
FastAPI is built on ASGI (Asynchronous Server Gateway Interface), making it extremely fast. It natively supports high-frequency WebSockets for live video/telemetry streaming and uses Pydantic for automatic data validation and interactive OpenAPI documentation (`/docs`).
Q7: What is the priority mechanism of the Emergency Stop button? ▼
The Emergency Stop (E-STOP) handler runs at the highest priority level in the backend. When activated, it immediately interrupts all active mission threads, sets motor speed outputs to zero, locks arm servo positions, and blocks incoming navigation commands until explicitly reset.
Q8: How does WebSockets differ from standard REST HTTP requests in this dashboard? ▼
Standard HTTP REST follows a request-response cycle (client asks, server answers). WebSockets establish a single persistent, full-duplex TCP connection, allowing the backend to stream live telemetry and camera frame data continuously to the UI 10+ times per second without request overhead.
Q9: Why are free wheel castors or differential steering used for this 4-wheel chassis? ▼
Differential steering allows the mobile robot to rotate in place (zero turning radius) by driving wheels on opposite sides in reverse directions. This is ideal for tight turns at the end of narrow agricultural crop rows.
Q10: What is the function of the soil moisture sensor in this system? ▼
The analog soil moisture sensor measures electrical resistance/capacitance in the soil. Lower resistance indicates high water content, enabling the robot to map field moisture levels while harvesting.
